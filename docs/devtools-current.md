# 当前微信开发者工具实测（2026-10-12）

本次使用腾讯官方稳定版 2.02.2608080（ARM64，官方配置标记日期 2026-09-30），在本机 macOS 导入本仓库 miniprogram/，游客模式、基础库 3.17.4。源码基准 07f7c41；这是当前官方工具模拟器实测，区别于此前浏览器布局适配和 2020 年模板编译器。

## 获取与运行

官方入口：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html 。页面脚本实际获取版本配置 https://devtools.wxqcloud.qq.com.cn/WechatWebDev/nightly/versions/config.json 。选取 stable/macOS/ARM64 包，保存于被忽略的 .local/wechat-devtools/。

包 SHA256：faeb39e0c3496747e6b958c05452af389bdbe428e13885cd4fb191e6c7172840。pkgutil --check-signature 确认 Tencent Technology (Shanghai) Company Limited 的 Apple Developer ID 签名及可信公证；codesign --verify --deep --strict 应用验证退出 0。用 pkgutil --expand-full 解包，在项目本地工具目录启动，没有执行全局安装脚本。

命令行服务端口默认关闭，cli open 返回 service port disabled；没有修改安全设置。通过工具界面选游客模式、导入 miniprogram、选择不使用云服务、运行本项目。工具导入时补入默认 project.config 选项；这些机器自动生成选项已恢复为仓库原配置。基础库等本机设置在 Git 忽略的 project.private.config.json。

## 仍缺的验收

游客模式的 wx.login 返回工具模拟值；生产 /riichi/api/wechat/login 返回503，服务器没有正式微信配置。因此未创建生产测试牌桌，未验证真实微信身份、扫码、小程序上传或安卓真机，也未看到正式登录后的记分／多人荣和／统计与联机牌桌原生运行。联机入口横屏的工具结果不能代替安卓锁屏方向或拖牌、测量、飞牌、长牌河与结算滚动实机验证。

控制台显示的错误是上述微信登录503；游客 API 限制及工具资源预加载警告同时存在，不能写成“无错误全部通过”。合法域名检查在游客模式被工具跳过，不能用IP请求成功证明正式域名通过。

网页生产仍为3e1c657，两套业务服务未重启；没有读取、复制、下载或备份真实资料。下一步可以在独立本地合成身份后端上继续检查原生业务页面；此类身份适配只用于开发，不证明真实微信登录。

## 本地合成身份下的原生业务实测（2026-10-12）

使用同一官方工具2.02.2608080／基础库3.17.4，真实原生页面调用独立本地HTTP服务、真实Store和SQLite；仅微信code换身份由测试适配器替代。新增 scripts/devtools-synthetic-server.mjs，仅明确传入 --synthetic 时启动，监听127.0.0.1随机端口；数据库与清单放.local/devtools-synthetic/run-*。不向生产环境提供模拟身份入口。

复跑：先npm run build，再运行 node scripts/devtools-synthetic-server.mjs --synthetic；临时把 miniprogram/config.js 的 apiBase 改为控制台输出的回环地址，在当前工具点击重新编译。首页最近牌桌打开预置四人桌，依次记分。测试后恢复config.js并重新编译，勿将回环地址提交或上传。游客模式的合法域名跳过不是正式域名验收。

## 三／四麻原生实测与横屏安全区（2026-10-12）

同一当前官方工具和本地合成身份服务，实际经Page→HTTP→OnlineManager→联机子进程运行三麻、四麻及电脑补位，没有把浏览器牌桌或固定模型当作原生对局。

- 三麻在界面创建，两个电脑补位、准备、开始成功。牌面PNG、牌背、宝牌和座位信息实际渲染；本人点击拔北后显示实体北和“拔北1”，后续电脑拔北数量也出现。
- 通过原生模拟器鼠标拖手牌到桌内，服务端记录本人弃p4，电脑继续合法行动；接口快照含实际三家弃牌、余牌48和下一摸牌决策。该结果验证工具里的触摸模拟、页面坐标测量和真实动作提交，不能代替安卓触摸手感或完整飞牌动画目视验收。
- 三麻解散恢复开桌入口。随后创建四麻，三个电脑补位、准备、开局成功；本人双点m4实际出牌，服务端各家弃牌与余牌64被核对，牌桌和三方牌背实际显示。最后四麻解散，页面恢复入口且HTTP room为null。
- 初次实际横屏844×346发现左侧刘海遮住牌背：CSS安全区值没有生效，wx.getWindowInfo仍返回390×671页面／390×844屏幕及竖屏safeArea，而真实.online测量是844×346。已加入online-safe-area，结合实际页面宽度／onResize尺寸确定横向留白。窗口信息尚为竖屏时，两侧保守取上下安全区最大值，适配旋转方向；正确横屏信息则使用实际左右值。
- 页面在onShow与onResize更新留白，旧测量回调或隐藏页面不覆盖当前结果；手牌、本人信息和结算面板使用同一安全区值。实际工具中左侧牌背完整避开刘海、所有本人牌可见。窄屏上方玩家标签随之调整，避开牌背与侧席副露。

168组布局适配检查通过，包括新增8组47px双侧留白的三／四麻视口与原160组特殊结算、长牌河、多副露／拔北组合；这些扩展几何检查仍是浏览器适配，不能写成168组微信实机。当前工具的直接视觉实测为上述实际三麻／四麻对局。235项常规检查（128 Node＋107规则）通过，日志.local/devtools-synthetic/online-tests.log与online-layout.log；真实HTTP观察快照只含本地合成牌局，位于run-UavV6M/。
