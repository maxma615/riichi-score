# 原生微信小程序：接手与发布

2026-10-11 已实现原生 WXML/WXSS/JavaScript 客户端，源码在 `miniprogram/`，不使用web-view包装。保留符番速查、四/三人桌、多人荣和独立符番、记分、撤回、逐局及每圈收支，新增算符清单、月度统计、同桌净点排名、微信登录与头像昵称填写。

## 导入

1. 安装微信开发者工具，导入 `mahjong-room/miniprogram`。`project.config.json` 的touristappid只用于本地源码导入，替换成实际AppID才可微信登录、预览与上传。
2. 修改 `config.js` 的apiBase为备案HTTPS域名下的独立接口，例如 `https://域名/riichi`。现有IP仅供网页访问，不能作为正式小程序合法域名。
3. 配置小程序request合法域名与头像download域名；头像由 `chooseAvatar` 主动选择，昵称由 `type=nickname` 填写。完成平台要求的隐私声明和备案。
4. 服务器独立服务的受保护.env配置 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`、`WECHAT_ENV_VERSION=trial`，然后重建该服务环境。AppSecret不可放到客户端、公开仓库或聊天。
5. wx.login code服务端换取openid，按appid+openid绑定稳定成员，再发30天应用token。服务器只保存token摘要，不返回openid、session_key或AppSecret。
6. 上传体验版后验证扫码；小程序码scene使用32位邀请代码，落到pages/room/index，选择空座位加入。扫码头像和昵称随成员显示；邀请不改变桌主。正式发布后env_version改release。

浏览器二维码依旧保留，指向网页版；小程序使用服务端wxacode.getUnlimited及小程序分享卡片。两种入口都保留独立记分服务，情侣空间账号不参与。网页旧身份和微信身份不按同名自动合并；成员代填的座位也不冒充微信身份。

## 统计口径

上海时间自然月、已提交且未撤回的历史记录。参与局数包括和牌及流局，结束标记不算一局；和牌统计区分自摸和荣和。放铳按局数计，双响只算一次放铳；被胡按支付给其他赢家的次数计，双响为两次，被他家自摸一次。净点含本场、立直与流局收支。

同桌收支是“与此人同桌时，你的累计净点”，不是对这个人的直接转账额；同一局可以计入多个同桌伙伴，因此不能把伙伴净点相加当总净点。最大正数为赢得最多，最小负数为输得最多；没有正/负数时不捏造赢家/输家。成员改名仍按ID统计；撤回直接从当前有效历史重算。

## 验证

`npm run sync:mini` 从服务端纯函数生成小程序CommonJS内核；改源函数后必须同步，不手改生成文件。`npm test` 实际78项通过，包含旧库迁移及旧4列sessions兼容、稳定微信身份、资料持久化、统计、权限、微信API边界、小程序页面逻辑与提交丢响应后的实际SQLite去重。`npm run test:browser` 实际8组通过，网页算符回填、月度统计、二维码解码、成员入桌及既有全流程均通过。

微信API用合成适配器验证协议，页面逻辑用wx适配器验证；这些不能替代微信编译器、开发者工具渲染或真机。当前未收到AppID/备案域名/AppSecret，尚未实际wx.login、小程序码生成、真机或审核发布。不是已经上线的小程序。后续验收：真实双微信身份、头像昵称选择、扫码/分享入桌、弱网重试、后台返回轮询、重启数据、撤回统计、权限与安卓真机。

网页与小程序都采用底部四入口；网页底部包含安全区留白，弹窗仍在导航上层。

网页与小程序的查点界面同步采用可点选交叉表，行列与档位高亮、结果滚动吸附。共享src/lookup.js通过sync:mini生成客户端模型，金额与无效组合逐格对计分内核验证。微信开发者工具及真机渲染仍待实际AppID提供后验收。
