# 线下整场结算与续桌

依据用户2026-10-25反馈，沿用现有网页／原生小程序与SQLite事务，不引入依赖。使用方案设计、实施计划和先验证后交付流程；用户已授权直接开发上线，不重复要求流程批准。

- 历史列表仅打开详情，撤回与删除在详情全部记录之后；结束页首屏给出名次、总点数、净点数及“原班人马再开一场”。
- 服务端rematch命令从已结束桌生成一张新桌，完整保留成员ID和规则，分数重置、起庄待选；同桌成员重复或并发点击进入同一个后续桌，版本冲突仍受控。旧记录保留。
- 第一局前允许排序、选择起庄、移出其他玩家后扫码或填写新玩家；第一局后冻结座位和场长。不能将自己移出导致失去管理入口。
- 东风／半庄按钮，默认半庄，新场按圈数最后一局换庄后自动结束；庄家连庄／途中流局继续；撤回末局恢复未结束。已有桌没有场长时不自动改变它的结束条件，可正常手动结束。
- 网页整行Pointer拖动，使用固定槽位计算、拖动位移与邻行让位；小程序原生touch同样显示位移，取消恢复，方向越界夹紧，不靠松手才重排。保留上移辅助按钮。

实施与验证：
1. Store/scoring增加续桌、开局前改人／场长、自动结束；先写内存和文件SQLite回归，覆盖权限、旧版本、幂等、并发续桌、删除后续桌、重启和撤回。
2. 网页改详情层级、续桌入口和拖动；浏览器覆盖移动中位移、取消、保存顺序、原班续桌及历史无删除入口。
3. 小程序源码同步，运行模板／运行时检查；未上传时明确说明，不冒充真机验收。
4. npm test、八组浏览器，检查线上文件／健康与合成内存事务。只重启记分，不读取或改写实际牌局。记录发布并提交推送GitHub。
