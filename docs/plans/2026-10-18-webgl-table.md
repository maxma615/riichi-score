# 真实三维牌桌渲染

用户明确要求真实几何计算，拒绝将平面牌背、阴影和CSS预投影当成立体牌。本轮以现有联机规则、语义DOM、本人手牌及交互为边界，替换网页的桌面公开物件渲染层。

## 设计

使用Three.js/WebGL透视相机、真实圆角长方体、材质与灯光，桌面、对手站牌、牌河、横牌、副露与拔北共用世界坐标及深度缓冲。牌的宽、高、厚分别独立，站牌底部接触桌面；牌面只作为几何正面的授权纹理。暗杠背面朝上，加杠叠在被碰横牌之上，整桌旋转由相对座位决定。只渲染服务端已公开的值。

保留本人手牌DOM的拖牌／键盘／点按、工具栏、结算和联机规则；现有公开牌DOM仅供语义与动画定位，由几何投影提供新坐标。屏幕旋转、缩放与桌布切换更新相机／材质，空闲时按需渲染，纹理及WebGL资源在卸载释放。WebGL故障不冒充三维成功，保留明确失败状态及现有可操作界面。

## 实施与验证顺序

1. 先写真实WebGL画布缺失的浏览器回归，以及纯三维布局实体数量／姿态／叠杠／旋转测试，观察失败。
2. 实现独立纯坐标模型，复用已有鸣牌解析；安装固定Three版本，建立几何牌体与桌面光照。
3. 集成现有公开事件与发牌／结果阶段，更新公开物件动画端点，避免牌与DOM飞行动画错位。
4. 实际浏览器截图核对站立面、白色顶边、侧面、深度遮挡、等腰梯形与手机尺寸；运行规则／权限／持久化与现有动作回归。
5. 提交并推送独立仓库；在本地构建后仅替换服务器前端资源，保留后台进程及现有牌局。不将网页WebGL验证当作小程序／安卓验收。
